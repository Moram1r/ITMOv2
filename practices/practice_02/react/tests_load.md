# Нагрузочные проверки

Файл ведёт OpenCode. Обсудите с агентом содержание и проверьте предложенный diff. Все дополнения и исправления поручайте агенту в чате.

| Сценарий | Нагрузка и длительность | Допустимый предел | Что измеряем | Подтверждение |
|---|---|---|---|---|
| Стабильная нагрузка на валидных диффах | warm-up 60с; 5 rps, 5 мин steady | p(95) <= 2.0 с; ошибки < 1% | k6: http_req_duration p(95), http_req_failed | Шаги: 1) запустить k6 со thresholds p(95)<=2.0s, error_rate<1%; 2) сохранить summary; 3) сверить OBS-1 duration/status; 4) повторить 2 раза — расхождение p95 <= 10% |
| Пиковая нагрузка | ramp 5→20 rps за 30с; плато 30с | p(95) <= 3.0 с; ошибки < 3% | k6 p(95), ошибки | Шаги: 1) запустить ramp; 2) проверить thresholds; 3) сверить OBS-1 статусы; 4) убедиться, что OUT-1 сохраняется |
| Oversize-флуд | 10 rps oversize (20001 симв.) 1 мин | 100% 413; 0 вызовов LLM | Доля 413; внешние вызовы | Шаги: 1) отправлять oversize; 2) проверить коды 413; 3) убедиться, что нет внешних вызовов; 4) OBS-1 не содержит diff/ответа |
| Fault-инъекция таймаутов | 2 rps, 2 мин; LLM >10с | 100% контролируемых OUT-1; исключений нет | Таймауты; OUT-1 | Шаги: 1) симулировать задержку >10с; 2) проверить, что ответы валидны по OUT-1; 3) OBS-1 статус timeout_handled; 4) k6 ошибок = 0 |

Если нагрузочное тестирование пока не требуется, объясните это OpenCode. Попросите записать причину и условие, при котором оно понадобится.
