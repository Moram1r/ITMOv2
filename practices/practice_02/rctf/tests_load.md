# Нагрузочные проверки

Файл ведёт OpenCode. Обсудите с агентом содержание и проверьте предложенный diff. Все дополнения и исправления поручайте агенту в чате.

| Сценарий | Нагрузка и длительность | Допустимый предел | Что измеряем | Подтверждение |
|---|---|---|---|---|
| Стабильная нагрузка на валидных диффах | warm-up 60с; 5 rps в течение 5 мин (k6 vus≈5) | http_req_duration p(95) <= 2.0 с; http_req_failed < 1% | k6: http_req_duration p(95), http_req_failed; статусы | OBS-1: duration, status; схема OUT-1 в ответе; 2 повтора — расхождение p95 <= 10% |
| Пиковая нагрузка | ступень: 5→20 rps за 30с; плато 30с | p(95) <= 3.0 с; ошибки < 3% | k6: p(95), ошибки; статусы | OBS-1 статусы и длительность; отчёт k6 c thresholds pass |
| Oversize-флуд | 10 rps запросов с diff > 20000 символов, 1 мин | 100% HTTP 413; 0 вызовов LLM | Доля 413; счётчики внешних вызовов | CASE.md API-1; OBS-1: отсутствует содержимое в логах; внешний вызов не зафиксирован |
| Fault-инъекция таймаутов | 2 rps, 2 мин; задержка LLM > 10с | 100% контролируемых OUT-1 ответов; исключений нет | Доля таймаутов; валидность OUT-1 | CASE.md REL-1/OUT-1; OBS-1: статус timeout_handled |

Если нагрузочное тестирование пока не требуется, объясните это OpenCode. Попросите записать причину и условие, при котором оно понадобится.
