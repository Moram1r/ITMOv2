# Practice 05 — окружение агента

Здесь подготовлено окружение OpenCode для сайта «Рентген проекта».
Рабочий базовый сайт находится в `project/`; его запуск описан в
[project/README.md](project/README.md). Описание задумки — в [PROJECT.md](PROJECT.md).

## Запуск

В терминале WSL:

```sh
cd /home/moramir/ITMO/ITMOv2/practices/practice_05
opencode
```

Если `opencode` отсутствует в PATH, в этой системе он установлен по пути
`~/.opencode/bin/opencode`: запусти его вместо короткой команды.
Если OpenCode уже был открыт, начни новую сессию из этой папки.

OpenCode автоматически читает `AGENTS.md` и `PROJECT.md`, обнаруживает навыки
и подключает MCP. Содержимое навыков загружается моделью по задаче;
в `AGENTS.md` описано, когда применять каждый из них. Для явного выбора можно
написать в запросе `@frontend-design`, `@test-driven-development` или
`@systematic-debugging`.

Настройки проверены на OpenCode **2.0.30**. Это формат V2; примеры из документации
старой версии могут с ним не совпадать. Провайдер и модель наследуются из
конфигурации репозитория. Глобальная конфигурация и другие практики не изменены.

## Что подключено

| Компонент | Для чего |
| --- | --- |
| `frontend-design` | Визуальный стиль, адаптивность, доступность, проверка интерфейса |
| `test-driven-development` | Проверка новой логики и исправлений через тесты |
| `systematic-debugging` | Воспроизведение ошибки, поиск причины, проверка исправления |
| Playwright MCP | Настоящий Chromium: действия на странице, консоль, скриншоты |
| `quality-gate` | Быстрая проверка окружения после `write`, `edit`, `patch` |
| `/check` | Проверка окружения и, когда оно появится, приложения |
| `/env-check` | Проверка регистрации в OpenCode и работоспособности MCP |

Навыки — компактные русскоязычные адаптации опубликованных материалов Anthropic
и Superpowers. Источники, точные ревизии, лицензии и изменения указаны в
[.opencode/SOURCES.md](.opencode/SOURCES.md).

Хук возвращает результат проверки в ответ инструмента, который видит модель.
Он проверяет конфигурацию, синтаксис скриптов и наличие зависимостей.
Правки через shell не вызывают этот хук; перед завершением задачи агент должен
самостоятельно выполнить полную проверку. Это помощник для проверки, а не
изоляция файлов или гарантия поведения модели.

Глобальный MCP `text-stats` из предыдущей практики здесь отключён.

## Особенности этой машины

Playwright запускается в WSL без графического окна. Chromium, недостающие
библиотеки Linux и временные результаты лежат в игнорируемых каталогах
`.opencode/.cache/` и `.opencode/.runtime/`. Системные пакеты не устанавливались.

## Проверки и восстановление

Зависимости и Chromium уже установлены на этой машине. Для восстановления
после нового клонирования или очистки кэша нужен Node.js 22+:

```sh
npm ci --prefix .opencode --ignore-scripts
npm --prefix .opencode run browser:install
```

В текущей Ubuntu установщик при необходимости скачивает недостающие библиотеки
из настроенных apt-репозиториев и распаковывает их в локальный кэш без `sudo`.
При заданном `HTTPS_PROXY` загрузка идёт через Windows-прокси, а размер и хеш
сверяются с apt-метаданными.
Для другой ОС набор системных библиотек может потребовать адаптации.

Из папки этой практики:

```sh
node .opencode/scripts/check.mjs
npm --prefix .opencode run test:hook
npm --prefix .opencode run doctor
npm --prefix .opencode run smoke:mcp
```

`doctor` поднимает временный OpenCode-сервер на loopback, создаёт пустую сессию
для инициализации, проверяет регистрацию и удаляет эту сессию. Запросов к модели
нет. `smoke:mcp` открывает временную страницу из памяти, проверяя действие
в браузере и PNG-скриншот. Эта страница не является приложением.
Для повторной проверки: `npm --prefix .opencode run smoke:mcp -- playwright`.

`/check` проверяет окружение, затем запускает `npm run check` в `project/`:
проверку типов, тесты и сборку приложения.

`AGENTS.md` — стандартное имя файла инструкций OpenCode; отдельный `AGENT.md`
не нужен.

## Spec Kit

Установлен [GitHub Spec Kit](https://github.com/github/spec-kit/tree/v1.2.3)
версии **1.2.3** из официального пакета PyPI `specify-cli`. CLI находится
в локальном Python-окружении `.opencode/.cache/spec-kit/venv/`, его зависимости
зафиксированы в `.opencode/requirements-spec-kit.txt`. Глобальный Python и
глобальная конфигурация OpenCode не менялись.

Перезапусти OpenCode в папке этой практики. В чате появятся команды:

- `/speckit.constitution` — согласование принципов проекта;
- `/speckit.specify` — описание фичи;
- `/speckit.clarify` — уточнение требований;
- `/speckit.plan` — технический план;
- `/speckit.tasks` — задачи реализации;
- `/speckit.analyze` — проверка согласованности документов;
- `/speckit.implement` — реализация;
- `/speckit.converge` — проверка соответствия реализации документам.

Установка добавила команды, шаблоны, служебные скрипты и шаблон конституции.
Конституция заполнена, первая фича `001-csharp-dependency-graph` описана
и реализована; её документы находятся в `specs/001-csharp-dependency-graph/`.
Стандартные обработчики событий Spec Kit отключены параметром `--events false`;
наш quality-gate продолжает работать. Git-расширение Spec Kit не устанавливалось.

В shell-инструменте OpenCode команда `specify` доступна автоматически.
В обычном терминале из `practice_05`:

```sh
.opencode/bin/specify version
.opencode/bin/specify integration status
```

Локальный плагин добавляет CLI в PATH только для shell-команд этого OpenCode
и указывает `SPECIFY_INIT_DIR` на `practice_05`, чтобы файлы не попадали в корень
учебного репозитория. Наши навыки, MCP и существующие команды сохранены.

После нового клонирования CLI восстанавливается отдельно от Node-зависимостей:

```sh
sh .opencode/scripts/install-spec-kit.sh
```

Нужен Python 3.11+ с поддержкой venv и доступ к PyPI. При первоначальной установке
из этой WSL пакеты загружались через существующий Windows-прокси; временный
загрузчик после установки остановлен. Повторный `specify init` для восстановления
CLI не требуется: файлы проекта Spec Kit уже находятся в репозитории.
