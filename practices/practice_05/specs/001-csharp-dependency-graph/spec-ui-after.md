# UI-спецификация вкладки «Граф» — версия «после»

**Статус:** согласована с командой логики. Источник истины по типам, лимитам
и правилам анализа — `contract.md` (решения раздела 11 подтверждены 2026-10-28).
Здесь только поведение интерфейса.

## 1. Цель и сценарии

После анализа ZIP пользователь открывает вкладку «Граф» и видит карту зависимостей
C#-проекта: файлы, проекты, пакеты и связи. Таблица файлов остаётся доступной.

1. **Знакомство.** Открыл «Граф» → увидел проекты и пакеты → выбрал проект →
   изучил связи → перешёл к `.csproj` в таблице.
2. **Проверка файла.** Выбрал `.cs`-узел → увидел входящие, исходящие и
   неразрешённые ссылки → перешёл к строке таблицы → вернулся с сохранённым выбором.
3. **Неполный архив.** Граф построен частично: виден баннер и счётчик
   неразрешённых ссылок, граф остаётся рабочим.

## 2. Структура вкладки

- Вкладки «Файлы» (по умолчанию) и «Граф» появляются после успешного анализа ZIP.
- Вкладка «Граф» содержит: панель счётчиков, переключатель «Список»/«Граф»,
  область графа или список, легенду, панель деталей, баннер предупреждений,
  кнопку «Повторить» (только для ошибки).
- После первого открытия вкладка остаётся смонтированной; переключение на
  «Файлы» скрывает её, но не сбрасывает результат, выбор, фильтр и масштаб.
- Счётчики: узлы, рёбра, неразрешённые ссылки, исключённые файлы
  (`obj/` + `bin/`, прочие, всего).
- Легенда: типы узлов и рёбер, пунктир — условная связь.

## 3. Действия

- Выбор узла, ребра или неразрешённой ссылки открывает детали.
- При выборе узла его входящие и исходящие рёбра подсвечиваются, остальные
  приглушаются; выбранное ребро сохраняет обычную подсветку.
- Наведение подсвечивает соседей; информация не передаётся только цветом.
- Zoom и pan мышью; клавиатура: `Tab` — элементы, `Enter`/`Space` — выбор,
  `Esc` — снять выбор, стрелки — перемещение по графу.
- «Показать в таблице файлов» доступно только при `tablePath !== null`;
  иначе пояснение, почему перехода нет.
- Фильтр «Показать неразрешённые» фильтрует только список ссылок, не граф.

## 4. Состояния

| Состояние | Что видно |
| --- | --- |
| `notStarted` | Граф не строится, пока вкладка не открыта |
| `building` | Индикатор без процентов; таблица доступна |
| `done` | Граф или список, счётчики, детали |
| `empty` | `NO_CSHARP_FILES` или пустой граф: объяснение, таблица доступна |
| `error` | Сообщение, «Повторить», таблица доступна |
| `limit` | Какой лимит превышен и на сколько, таблица доступна |

`partial` как состояние вкладки не существует: неполнота показывается баннером
при неразрешённых ссылках или предупреждениях. При этом узел может иметь
`status: 'partial'` — это поле узла, а не состояние вкладки.
`large` — режим отображения, а не состояние.

## 5. Большой граф

Пороги отображения из `contract.md`:

- не более 200 узлов / 500 рёбер — обычный интерактивный граф, по умолчанию
  открыт «Граф»;
- выше — по умолчанию открыт полный список; граф показывает не более 200 узлов
  с наибольшей суммарной степенью (входящие + исходящие) и не более 500 связей,
  оба конца которых попали в выбранные узлы, с наибольшей суммой степеней
  концов, с подписями «показано X из Y» для узлов и рёбер;
- выше 1000 узлов / 3000 рёбер — только полный список, счётчики и пояснение,
  переключатель «Граф» недоступен.

Список остаётся полным в пределах лимитов анализа. Подписи «показано X из Y»
относятся к упрощённому графу, а не к списку. Кластеризации и скрытого усечения нет.

## 6. Ошибки

- Ошибка графа не очищает сводку и таблицу.
- `NO_CSHARP_FILES` показывается как пустое состояние, не как красная ошибка.
- Неизвестная ошибка: «Не удалось построить граф зависимостей» + «Повторить».
- Тексты `message` из `GraphResult` и `GraphAnalysisError` показываются как есть.
- Все пути, имена и сообщения экранируются при выводе.

## 7. Доступность и адаптивность

- Все действия доступны с клавиатуры, фокус видим.
- У узлов и рёбер есть текстовые подписи и `aria`-описания.
- На экране шириной 375 px граф и детали располагаются вертикально, список
  читается без горизонтальной прокрутки.
- Учитывается `prefers-reduced-motion`.

## 8. Границы MVP

Нет подсветки циклов, редактирования графа, экспорта, отмены построения,
поиска по графу и сохранения состояния между сессиями.

## 9. Условия приёмки

1. ZIP в пределах лимитов: таблица и сводка прежние, «Файлы» активна по умолчанию,
   граф строится при первом открытии вкладки и не перезапускается при переключении.
2. Основной ZIP с `ProjectReference`, `PackageReference` и `using` даёт ожидаемые
   узлы и рёбра; счётчики совпадают с массивами.
3. Неразрешённые ссылки не рисуются на графе, видны списком и счётчиком;
   фильтр работает, таблица не затронута.
4. При превышении хотя бы одного комфортного порога список открывается
   первым; в упрощённом графе «показано X из Y» верно для узлов и рёбер;
   выше максимума доступен только полный список.
5. Ошибка и лимит графа оставляют таблицу доступной; «Повторить» работает
   для ошибки, для лимита и пустого состояния повтора нет; новый архив
   сбрасывает граф, выбор, фильтр и масштаб; устаревший результат не показывается.

## 10. Что сохраняется

Загрузка ZIP, сводка, таблица (путь, расширение, размер), лимиты
20 МиБ / 2000 / 100 МиБ, существующие ошибки, «Выбрать другой архив»,
локальный анализ без сети и логирования. Пользователь, не открывающий «Граф»,
не видит изменений.
