# Research: Граф зависимостей C#-проекта

**Дата**: 2026-10-28 | **План**: [plan.md](./plan.md) | **Спека**: [spec.md](./spec.md)

## R1. Чтение содержимого ZIP

- **Decision**: переоткрывать архив через `ZipReader(new BlobReader(file))`
  из уже подключённого `@zip.js/zip.js/index-native.js`; содержимое читать
  `entry.getData(new TextWriter())`.
- **Rationale**: зависимость уже есть, `TextWriter` экспортируется, web workers
  отключены для совместимости с тестами. Центральный каталог уже проверен
  `analyzeZipFile`, повторная проверка лимитов ZIP не нужна.
- **Alternatives**: `FileReader`/`DecompressionStream` — больше кода и другая
  обработка кодировок; `JSZip` — новая зависимость.

## R2. Разбор C# без Roslyn

- **Decision**: собственный сканер. Сначала убрать `//`, `/* */`, строковые
  литералы (`"..."`, `@"..."`, `$"..."`, `"""..."""`) и char-литералы, затем
  найти `using`, `using static`, alias и `namespace` регулярными выражениями
  по очищенному тексту.
- **Rationale**: C# не компилируется и не исполняется; нужны только объявления
  namespace и using. Roslyn в браузере — тяжёлая зависимость и лишний риск.
- **Alternatives**: Roslyn/WASM — запрещено границами MVP; полный парсер C# —
  несоизмерим с задачей.
- **Ограничения**: using внутри блоков трактуются как файловые; `scopeNamespace`
  хранится в `UsingRef` и заполняется только для file-scoped namespace.
  `using static` и alias разрешаются по правилам R5 и не создают фиктивных рёбер.
  Препроцессорные условия `#if` в `.cs` не вычисляются; using внутри всех ветвей
  считаются присутствующими, условность поддерживается только для `.csproj`.

## R3. Разбор `.csproj`

- **Decision**: сканер тегов с сохранением стека элементов. Для
  `ProjectReference` и `PackageReference` читаются `Include`, `Version`
  (атрибут или дочерний элемент), `Condition`; условие наследуется от
  `ItemGroup`/`When`/`Choose` и объединяется с вложенными через ` && `
  от внешнего к внутреннему. `ProjectReference Include` разрешается
  относительно каталога проекта; небезопасный путь даёт `PROJECT_NOT_FOUND`.
  XML-комментарии `<!-- -->` игнорируются. `TargetFramework(s)` извлекаются
  из текста элементов.
- **Rationale**: не нужен DOM/DOMParser, работает в Node-тестах; покрывает
  реальные файлы SDK-style проектов.
- **Alternatives**: `DOMParser` — недоступен в node-тестах без jsdom и хуже
  переносит пространства имён; полноценный XML-парсер — новая зависимость.
- **Ограничения**: `Directory.Packages.props`, `Directory.Build.props` и
  импорты не анализируются; это явно вне MVP. MSBuild-свойства в путях
  и версиях не раскрываются: ссылка с нераскрытым путём попадает
  в `unresolved`, версия сохраняется как текст.

## R4. Принадлежность `.cs` проекту

- **Decision**: ближайший `.csproj` вверх по директориям; при нескольких
  кандидатах — первый по побайтовому порядку нормализованного пути
  и предупреждение `MULTIPLE_PROJECTS_IN_DIR`.
- **Rationale**: соответствует обычной структуре репозитория и не требует `.sln`.
- **Alternatives**: разбор `.sln` — лишний формат и ложные связи.

## R5. Сопоставление `using` с namespace

- **Decision**: точное совпадение **с учётом регистра**, как в C#; пути при этом
  нормализуются без учёта регистра.
  - один или несколько файлов объявляют один и тот же namespace — ребро
    `using`/`namespace-match` к каждому другому файлу; если namespace объявлен
    в самом файле-источнике, ссылка пропускается;
  - точного совпадения нет, но есть совпадение в другом регистре —
    `unresolved` с `NAMESPACE_CASE_MISMATCH` и кандидатами, без ребра;
  - точного совпадения нет, но есть объявленные namespace с этим префиксом —
    `unresolved` с `NAMESPACE_NOT_FOUND` и списком кандидатов;
  - совпадений нет — `unresolved` с `EXTERNAL_NAMESPACE`;
  - `System` и `System.*` не дают ни ребра, ни `unresolved` — только
    `systemUsingCount`, включая static и alias;
  - `using static` — без ребра и `STATIC_USING_UNSUPPORTED`, кроме
    `System`/`System.*`; кандидаты — объявленные namespace-префиксы цели,
    от длинного к короткому;
  - alias — ребро только при точном совпадении цели с namespace, иначе
    `ALIAS_TARGET_UNSUPPORTED` (кроме `System`/`System.*`) с такими же
    кандидатами;
  - повторные `using` не создают дубликатов рёбер; у неразрешённых ссылок
    повторы агрегируются, `count` — число вхождений;
  - `using` на собственный namespace и `from === to` не создают ребра и не
    попадают в `unresolved`.
- **Rationale**: C# различает регистр; нечёткое совпадение дало бы ложную связь
  и нарушило бы принцип «честного графа».
- **Alternatives**: сравнение без учёта регистра — ложные рёбра; нечёткое
  сопоставление по суффиксу — ещё больше ложных связей.

## R6. Пакеты и версии

- **Decision**: один узел `package:<lowercase id>`; версии — отсортированный
  массив уникальных значений; ребро хранит `packageVersion`; при разных версиях
  создаются разные рёбра.
- **Rationale**: соответствует контракту; не требует разрешения версий.
- **Alternatives**: узел на версию — визуальный шум; сравнение версий — вне MVP.

## R7. Визуализация графа

- **Decision**: `@xyflow/react` 12.12, ленивая загрузка вкладки.
- **Rationale**: pan/zoom, рёбра, выбор и фокус из коробки; MIT; нет сети.
- **Alternatives**: собственный SVG — больше кода, ручной zoom/pan и
  клавиатурная навигация; Cytoscape — тяжелее и менее React-нативный.

## R8. Раскладка

- **Decision**: слоистая раскладка по глубине зависимостей. BFS запускается
  от узлов без входящих рёбер в порядке `id`; после обхода, если остались
  непосещённые узлы (циклы), BFS повторяется от наименьшего `id` из них с
  глубиной 0. Глубина узла фиксируется при первом посещении, обратные рёбра
  её не меняют. Внутри слоя — сортировка по `id`. Координаты фиксированные,
  без физики.
- **Rationale**: детерминированно, быстро, не требует layout-движка; циклы
  не ломают результат и не дают случайных координат.
- **Alternatives**: force-directed — недетерминированно и дорого; dagre/elk —
  новая зависимость.

## R9. Большой граф

- **Decision**:
  - ≤ 200 узлов и ≤ 500 рёбер — полный интерактивный граф, по умолчанию «Граф»;
  - выше хотя бы одного комфортного порога, но ≤ 1000/3000 — по умолчанию
    «Список»; граф показывает не более 200 узлов с наибольшей суммарной
    степенью (`входящие + исходящие`; при равенстве — по `id`) и не более
    500 связей, оба конца которых попали в эти узлы, с наибольшей суммой
    степеней концов (при равенстве — по `id` ребра), с отдельными подписями
    «показано X из Y» для узлов и рёбер;
  - выше 1000 узлов или 3000 рёбер — только полный список; переключатель
    «Граф» недоступен.
- **Rationale**: сохраняет отзывчивость и не скрывает данные: полный список
  всегда доступен.
- **Alternatives**: кластеризация — сложна и меняет смысл графа; виртуализация
  React Flow — не гарантирует производительность при 3000 рёбрах.

## R10. Ленивый запуск и устаревшие результаты

- **Decision**: `GraphTab` запускает `analyzeCsharpGraph` при первом
  `active === true`; хранит `status` и `result`; при новом файле инкрементирует
  токен и игнорирует ответы со старым токеном.
- **Rationale**: соответствует контракту; таблица не ждёт граф.
- **Alternatives**: запуск сразу после `analyzeZipFile` — замедляет основной
  сценарий; отмена через `AbortController` — zip.js не поддерживает частично.

## R11. Тестирование

- **Decision**: unit-тесты на парсеры, сборку, лимиты и детерминизм; ZIP
  собирается в тестах через `ZipWriter` (как в `analyzer.test.ts`). UI —
  Playwright MCP: успех, пустое состояние, ошибка, лимит, клавиатура, экран 375 px.
- **Rationale**: не добавляет тестовых библиотек; проверяет реальные ZIP.
- **Alternatives**: snapshot-тесты React — новая зависимость и хрупкость.

## R12. Безопасность и приватность

- **Decision**: не читать `.env`, ключи, сертификаты и файлы вне `.cs`/`.csproj`;
  не логировать содержимое; не передавать данные в сеть; экранировать пути и
  сообщения силами React; не использовать `eval`/`new Function`.
- **Rationale**: соответствует конституции и контракту.
- **Alternatives**: нет.

## R13. `tablePath` и переход в таблицу

- **Decision**: хранить исходный путь записи ZIP; `tablePath` — исходная
  строка из `AnalysisResult.files`, у которой нормализованный путь совпадает
  с `path`. При дубликатах (сравнение без учёта регистра) — один узел
  `unknown`, `tablePath: null`, текст не читается, предупреждение
  `DUPLICATE_PATH`.
- **Rationale**: UI ищет строку точным сравнением и не ошибается с регистром
  или слэшами.
- **Alternatives**: нечёткий поиск — риск подсветить не тот файл.

## R14. Статусы узлов

- **Decision**:
  - `source`: `known` — прочитан и разобран; `partial` — прочитан с замечанием
    разбора или пустым namespace; `unknown` — не прочитан (> 1 МиБ или ошибка).
  - `project`: `known` — `.csproj` прочитан и все исходники `known`; `partial` —
    есть `partial`/`unknown` исходник или замечание; `unknown` — `.csproj`
    не прочитан.
  - `package`: всегда `known`.
- **Rationale**: пользователь видит, где граф неполон, а не только общий баннер.
- **Alternatives**: один общий флаг `partial` у результата — теряется локальность.

## R15. Счётчики `GraphStats`

- **Decision**:
  - `projectCount`, `sourceFileCount`, `packageCount` — число узлов соответствующего `kind`;
  - `namespaceCount` — уникальные объявленные namespace (с учётом регистра);
  - `systemUsingCount` — уникальные пары `(fromId, target)` для `System`/`System.*`,
    включая `using static` и alias;
  - `externalUsingCount` — уникальные пары `(fromId, target)` для `using` без
    точного namespace, кроме `System`/`System.*`, включая `using static` и alias;
  - `unresolvedCount` — сумма `count` по всем `UnresolvedItem`.
- **Rationale**: счётчики должны быть проверяемыми и не зависеть от дублей.
- **Alternatives**: считать вхождения — цифры зависят от повторов и хуже тестируются.

## R16. Глубина анализа

- **Decision**: граф содержит только прямые связи; глубина анализа — 1,
  рекурсивного обхода зависимостей нет. Объём ограничен `maxNodes` и
  `maxEdges`, а раскладка BFS работает по уже построенному графу и не читает
  ZIP повторно.
- **Rationale**: конституция требует явной границы обхода; для прямых ссылок
  глубина 1 является этой границей, а лимиты узлов и рёбер ограничивают объём.
- **Alternatives**: транзитивное замыкание — не требуется MVP и дало бы
  квадратичный рост рёбер.
