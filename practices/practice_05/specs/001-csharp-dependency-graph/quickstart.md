# Quickstart: проверка графа зависимостей C#-проекта

**Фича**: `001-csharp-dependency-graph` | **Дата**: 2026-10-28

## Подготовка

```bash
cd project
npm install          # при первом запуске, добавит @xyflow/react
npm run dev          # адрес вида http://localhost:5173
```

Требования: Node.js 18+, современный браузер. Сервер и сеть не используются.

## Тестовый архив

Соберите ZIP со структурой:

```text
Demo/
├── A/
│   ├── A.csproj        # ProjectReference ..\B\B.csproj
│   │                   # PackageReference Newtonsoft.Json 13.0.3
│   └── Program.cs      # using B.Services; using System;
├── B/
│   ├── B.csproj
│   └── Services.cs     # namespace B.Services;
├── obj/
│   └── Generated.cs    # должен быть исключён
└── README.md
```

## Сценарии

### 1. Основной сценарий

1. Загрузите ZIP и нажмите «Проанализировать».
2. Проверьте: сводка и таблица прежние, «Файлы» активна по умолчанию.
3. Откройте «Граф».

Ожидается: индикатор построения, затем 2 проекта, 2 файла, 1 пакет;
связи `A → B` (project-reference), `A → Newtonsoft.Json` (package-reference),
`Program.cs → Services.cs` (using). Счётчики совпадают с числом узлов и рёбер.
Замерьте: построение ≤ 5 с, переключение вкладок и сброс ≤ 1 с.

### 2. Детали и переход в таблицу

1. Выберите `Program.cs`.
2. Проверьте входящие/исходящие связи и статус.
3. Нажмите «Показать в таблице файлов».

Ожидается: при выборе `Program.cs` его исходящая связь подсвечена, остальные
связи приглушены; открывается «Файлы», строка `Demo/A/Program.cs` подсвечена.
Возврат в «Граф» сохраняет выбор. Для пакета переход недоступен с пояснением.

### 3. Неразрешённые ссылки

Добавьте в `Program.cs` строки `using Missing.Namespace;`, `using b.services;`
(неверный регистр) и `using static B.Services.Helper;`, а в `A.csproj` —
`ProjectReference ..\C\C.csproj` без файла `C.csproj`.

Ожидается: счётчик неразрешённых ссылок равен 4 (внешний namespace, неверный
регистр, `using static`, отсутствующий проект), все видны в списке, на графе
нет фиктивных узлов и рёбер; фильтр «Показать неразрешённые» работает.
`using B.Services` с правильным регистром по-прежнему даёт ребро.

### 4. Пустой архив

Загрузите ZIP только с `README.md`.

Ожидается: вкладка «Граф» показывает пустое состояние с объяснением,
таблица и сводка остаются доступными, повтор недоступен.

### 5. Мягкий лимит файла

Добавьте `.cs`-файл больше 1 МиБ.

Ожидается: узел со статусом «неизвестно», предупреждение, граф строится дальше.

### 6. Большой граф и жёсткие лимиты

1. Соберите ZIP с 250 узлами и 600 рёбрами (например, скриптом).
2. Откройте «Граф».

Ожидается: по умолчанию открыт полный список; переключатель «Граф» показывает
не более 200 узлов с наибольшей суммарной степенью (входящие + исходящие)
и 500 связей, оба конца которых попали в выбранные узлы, с наибольшей суммой
степеней концов; подписи «показано X из Y» верны для узлов и рёбер. Для графа выше 1000 узлов или
3000 рёбер переключатель «Граф» недоступен, остаётся полный список.

Жёсткие лимиты проверяются unit-тестами с уменьшенными лимитами:
`maxTextBytes`, `maxNodes`, `maxEdges`. Для состояния «лимит» в UI используйте
ZIP с одним `.csproj` и 3001 различным `PackageReference` (`LIMIT_NODES`);
таблица остаётся доступной, повтора нет. Остальные жёсткие лимиты проверяются
unit-тестами.

### 7. Клавиатура и экран 375 px

1. Пройдите вкладки и граф с клавиатуры: `Tab`, `Enter`/`Space`, `Esc`.
2. Установите ширину 375 px.

Ожидается: видимый фокус, все действия доступны, граф и детали расположены
вертикально, горизонтальной прокрутки страницы нет.

## Автоматические проверки

```bash
cd project
npm run check
```

Ожидается: `tsc --noEmit` без ошибок, все тесты Vitest зелёные, `vite build`
успешен.

Новые тесты:

- `test/graph-parser.test.ts` — using/namespace, `using static`, alias, комментарии, литералы, XML-комментарии, csproj, вложенные `Condition`, версия пакета;
- `test/graph-builder.test.ts` — проекты, пакеты, точный регистр namespace, `NAMESPACE_CASE_MISMATCH`, static/alias, self-edge, дедупликация, статусы, подписи `label`, счётчики, `tablePath`, дубликаты путей, детерминизм, отсутствие исходного текста;
- `test/graph-limits.test.ts` — размер файла, текст, узлы, рёбра, `NO_CSHARP_FILES`, `.env`/ключи не читаются.

## Playwright-проверка

Запустить dev-сервер из `project/`, открыть адрес, выполнить сценарии 1–7.
Зафиксировать: скриншот вкладки «Граф», пустое состояние, ошибку/лимит,
экран 375 px; проверить отсутствие ошибок в консоли. После проверки остановить
только запущенный вами dev-сервер.
