# Последовательная отладка

Сначала установи причину, затем меняй код.

1. Прочитай полное сообщение ошибки. Запиши конкретное действие или команду,
   входные данные и ожидаемый результат. Воспроизведи сбой.
2. Проверь последние изменения, версии зависимостей и рабочую директорию.
   Найди ближайший работающий пример. Для API сверяйся с документацией через Context7.
3. Найди границу, где результат становится неверным: загрузка, чтение ZIP,
   анализ или отображение. Добавляй минимальную диагностику без секретов
   и содержимого пользовательских файлов.
4. Сформулируй одну проверяемую гипотезу. Проверь её самым маленьким изменением.
   Не меняй одновременно зависимости, конфигурацию и логику.
5. Для ошибки логики добавь тест, который воспроизводит проблему, затем исправление.
   Для окружения повтори исходную команду. Для UI повтори сценарий в Playwright.
6. Запусти проверки проекта. Убери временную диагностику и сообщи причину,
   исправление и фактический результат.

Если несколько попыток не подтвердили гипотезу, вернись к данным и сузь
воспроизведение. Не накапливай догадки в коде. Если причина во внешней сети
или недоступном сервисе, отдельно проверь подключение и покажи ограничение;
не выдавай заглушку за исправление.

Источник и изменения перечислены в `../../SOURCES.md`.
