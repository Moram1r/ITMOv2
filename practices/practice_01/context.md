## Context Pack для первого рабочего сценария

### Факты и правила

- SEC-1: перед отправкой во внешний LLM из diff удаляются токены, пароли и приватные ключи. (CASE.md)
- API-1: diff длиннее 20 000 символов отклоняется с HTTP 413. (CASE.md)
- REL-1: внешний LLM-вызов имеет timeout 10 секунд; ошибка превращается в контролируемый ответ. (CASE.md)
- OUT-1: ответ содержит `summary`, массив `risks` (<=3 элементов с `file`, `line`, `evidence`, `risk`) и массив `checks`. (CASE.md)
- SCOPE-1: сервис только советует; он не пишет код и не выполняет действия в GitHub. (CASE.md)
- QA-1: риск включается в ответ, только если подтверждён строкой diff или правилом репозитория. (CASE.md)
- OBS-1: в лог пишутся только `request_id`, длительность и статус; содержимое diff и ответа не логируется. (CASE.md)

### Формат входа и результата

- Вход: JSON с полем `diff` (строка, исходный текст diff PR). (TRAINING_PR.diff: app/api.py:35-37)
- Выход AS IS: `{"comment": str}`. (TRAINING_PR.diff: app/review_service.py:22)
- Выход TO BE по OUT-1: объект с `summary: str`, `risks: [{file, line, evidence, risk}]` (<=3), `checks: [str]`. (CASE.md)

### Ограничения и запрещённые действия

- Не отправлять секреты во внешний LLM; секреты должны быть редактированы. (SEC-1)
- Отклонять oversize diff > 20000 символов кодом 413. (API-1)
- Прерывать внешний вызов по таймауту 10с и возвращать контролируемый ответ. (REL-1)
- Не выполнять approve/merge/изменения кода; только советовать. (SCOPE-1)
- Не логировать содержимое diff/ответа; логировать только request_id, длительность, статус. (OBS-1)
