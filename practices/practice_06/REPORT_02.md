## 3. Оставшиеся и новые проблемы

### P2-1. Неограниченный рост состояния rate limit по уникальным именам

- Где: `lab/service.py:58,347-363`.
- Как воспроизвести: отправить много `POST /login` с разными значениями `username` и неверным паролем. В локальной проверке 500 разных несуществующих имён увеличили `len(shop.failed_logins)` с 0 до 500.
- Фактический результат: для каждого нового имени создаётся отдельная запись; устаревшие записи очищаются только при следующем запросе с тем же именем. Общего лимита числа ключей или периодической очистки нет.
- Ожидаемый результат: объём состояния аутентификации должен быть ограничен даже при запросах с уникальными именами.
- Влияние: анонимный атакующий может постепенно исчерпать память процесса, обходя лимит попыток ротацией имени пользователя.
- Что требуется: ограничить число хранимых ключей/окно состояния, удалять устаревшие записи и добавить тест нагрузки с уникальными именами.
- Минимальное воспроизведение из каталога `lab`:

  ```python
  from service import Shop
  shop = Shop()
  try:
      for i in range(500):
          shop.dispatch("POST", "/login",
                        {"username": f"unknown-{i}", "password": "bad"}, {})
      print(len(shop.failed_logins))  # 500
  finally:
      shop.close()
  ```

## 5. Проверка на обход и читерство

- В `test*.py` не найдены `skip`, `xfail`, `expectedFailure`, `TODO` или `FIXME`.
- Ключевые проверки реализованы в `service.py`, а не только в тестах или prompt: `require_session`/`require_staff`, фильтрация по владельцу и авторизация каждого инструмента.
- Принудительная передача опасного `decision` проверяется отдельно от поведения модели; у клиента `export_profiles` отклоняется сервером.
- `sandbox.py` в доступном снимке сохраняет проверку разрешённого корня; тесты на parent path и symlink проходят. Неизменность файла относительно исходного коммита не подтверждена из-за отсутствия Git-истории.
- В production-коде не обнаружены `eval`, `exec`, `subprocess`, `os.system` или клиентские HTTP-вызовы. Найденные `urlopen` используются только в локальных HTTP-тестах.
- Ограничение размера реализовано до чтения тела: `service.py:435-441` сравнивает `Content-Length` с `MAX_BODY`.
- Ошибки `ApiError` преобразуются в контролируемые ответы; неожиданные исключения логируются на стороне сервера, клиент получает общее сообщение (`service.py:453-457`).
- Журнал содержит только метод, путь без query и статус (`service.py:135-136`); очередь имеет максимальную длину 200 (`service.py:62`).
- Проверка модели `shop-planner` не запускалась: архив не содержит конфигурацию/среду запуска агента. Защита исполнителя проверена прямой передачей опасного решения.
